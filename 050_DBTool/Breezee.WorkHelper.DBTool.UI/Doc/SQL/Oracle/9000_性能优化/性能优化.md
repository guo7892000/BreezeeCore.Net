## 性能优化
如果你在用PL/SQL做数据库开发，肯定遇到过查询慢、执行效率低下的情况。数据库的性能直接影响到整个系统的速度，特别是在处理大数据量时，
优化SQL执行效率就显得尤为重要。

### 给需要的字段建索引
索引就像是数据表的“目录”，可以让查询更快找到目标数据。想象一下，如果你要查一个电话本里的人名，如果没有索引（就是没做排序），
你得一个个查过去，效率很低。但如果你做了索引（像给人名排序），就能快速找到。
### 避免SELECT *，明确列出需要的字段
很多人在写查询的时候习惯用“SELECT *”，就是不管什么字段都查。虽然看起来方便，但这会浪费很多系统资源。要知道，每次查询，
数据库都会把所有字段的值都给你拿回来。为了提高效率，最好只选你需要的字段。
### 优化连接操作
在多个表之间做JOIN的时候，连接方式选得好，性能差别可是天壤之别。比如，INNER JOIN通常比LEFT JOIN效率高，尤其是在连接大数据表时。
对于大表连接的情况，可以考虑使用子查询，或者使用EXISTS代替IN，也能提升执行效率。
### 尽量避免IN操作符
看到“IN”条件，很多开发者就自然地想到能用它来做多值查询。但其实，IN语句的效率在大数据量下表现并不好。最好将IN替换为JOIN操作，或者改成EXISTS语句。
### 减少不必要的数据库操作
在PL/SQL代码中，如果有地方涉及到循环数据库查询操作，最好尽量减少。每次循环进行数据库查询，都会增加执行时间，拖慢程序的速度。
比如你在一个大表中循环查询数据，不如把这些数据一次性取出来，放在内存中做处理。
### 使用批量操作（FORALL）
当你需要插入、更新或者删除大量数据时，PL/SQL的FORALL语句能够让你一次性处理成千上万条记录，而不是一个个地操作。对于大量数据的批处理，FORALL无疑是一个非常高效的选择。
### 尽量避免显式游标
游标是PL/SQL中用来处理查询结果的一种方式。虽然游标非常常用，但它会增加一定的开销，特别是在查询结果集较大的时候。如果可以，尽量使用隐式游标（比如SELECT INTO）。
显式游标需要手动打开、关闭，增加了代码的复杂度，也会拖慢执行速度。
### 分析执行计划，找出瓶颈
PL/SQL优化不仅仅是写代码时的考虑，执行过程中，也需要定期查看SQL的执行计划。执行计划能帮助你看到SQL执行的详细步骤，比如是否进行全表扫描、是否有不必要的连接等。
通过查看执行计划，你可以发现哪些操作耗时过长，然后有针对性地优化这些部分。

### 存储过程的调优
PLSQL Developer Profiler是一个非常强大的plsql 性能优化工具，可获取已执行的每行代码，时间、次数的消耗情况。  
1、右键存储过程，单击【测试】或【Test】。  
2、单击测试后，会弹出一个测试窗口，此时点击【创建概览图报告】或【create profiler report】。  
3、点击【执行】或者【F8】执行存储过程，并尽量让其执行完成。  
4、点击【概览图】或者【Profiler】页签，然后点击【合计时间】或【Total time】列，查看耗费最多时间的SQL语句。  
5、右击某一行，选择[Go to unit line/转到单元行] ，这样就会直接跳到对应的源代码位置。  
针对SQL语句的优化，虽然按F5也能查看到一些使用索引和全表扫描情况，但还是建议放到存储过程中来调试，那样能跟踪到哪一行耗时最多，更直观。
