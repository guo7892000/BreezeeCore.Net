### 临时表
全局临时表（Global Temporary Table, GTT）  
在 Oracle 数据库中，ON COMMIT 子句是与临时表一起使用的，用以控制临时表中的数据在事务提交后的行为。
Oracle 支持两种类型的临时表：会话级临时表（session-specific temporary tables）和事务级临时表（transaction-specific temporary tables）。   
1、事务级临时表  
事务级临时表在事务提交或回滚时仍然存在，直到下一次事务提交。它们可以使用 ON COMMIT PRESERVE ROWS 选项。这意味着当事务提交时，表中的数据不会被删除，而是保持不变，直到下一次事务提交或显式删除。  
```
CREATE GLOBAL TEMPORARY TABLE temp_emp_data (
  emp_id NUMBER,
  emp_name VARCHAR2(100)
) ON COMMIT PRESERVE ROWS; --在事务提交后保留数据，直到下一次事务提交或显式删除。
```
使用场景  
‌数据暂存‌：当你需要在多个步骤中使用同一组数据但又不想在每次操作后都重新加载数据时，可以使用事务级临时表。  
‌中间结果存储‌：在复杂的事务处理中，可能需要暂存中间结果以便后续步骤使用。  
2、会话级临时表  
会话级临时表在会话期间存在，直到会话结束。它们通常使用 ON COMMIT DELETE ROWS 选项，这意味着当事务提交时，表中的所有数据将被删除。  
```
CREATE GLOBAL TEMPORARY TABLE temp_emp_data (
  emp_id NUMBER,
  emp_name VARCHAR2(100)
)
ON COMMIT DELETE ROWS;
```
3、注意事项  
‌存储限制‌：虽然全局临时表很有用，但请注意它们仍然占用数据库资源。过多的全局临时表可能会影响性能和资源管理。  
‌清理‌：虽然 ON COMMIT PRESERVE ROWS 保持了数据，但在不再需要时，你应该显式删除这些数据或通过其他机制（如周期性清理脚本）管理它们。   
‌权限‌：创建和使用全局临时表需要相应的数据库权限。  
通过合理使用 ON COMMIT PRESERVE ROWS，你可以更灵活地管理事务中的数据，特别是在需要跨多个步骤重用数据的情况下。
