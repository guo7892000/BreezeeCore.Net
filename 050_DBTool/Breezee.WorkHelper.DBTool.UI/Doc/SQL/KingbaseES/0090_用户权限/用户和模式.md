## Oracle兼容模式下的金仓数据与Oracle数据库中用户、模式的差异
KingbaseES 在 Oracle 兼容模式下，虽然提供了高度兼容的语法和功能，但在核心的用户（User）与模式（Schema） 架构上，两者存在根本性差异。			
核心区别在于：在Oracle中，用户和模式是“一体”的；而在KingbaseES中，它们是“分离”的。			
核心差异：用户与模式的关系			
Oracle：用户即模式，一一对应			
在Oracle中，创建一个用户时会自动创建一个与之同名的模式（Schema）。这个模式是该用户的“私有领地”，默认情况下，用户只能访问自己模式下的对象，两者是紧密绑定、不可分割的。			
KingbaseES：用户与模式相互独立			
这是两者最本质的区别。KingbaseES将用户和模式视为两个独立的概念。			
			
用户（User）：是一个用于登录数据库的账户实体。			
模式（Schema）：是一个用于组织和隔离数据库对象的逻辑命名空间。			
这种设计带来了更高的灵活性：			
			
多对多关系：一个用户可以拥有（或访问）多个模式；反过来，一个模式也可以被多个用户共享。			
逻辑分组：你可以将不同应用或功能模块的表、视图、函数等放在不同的模式下进行管理，实现更清晰的逻辑隔离。			
避免对象丢失风险：在Oracle中，如果删除了一个用户，其同名模式下的所有对象也会被级联删除。而在KingbaseES中，由于用户与模式解绑，你可以在不删除模式的情况下删除或停用一个用户，从而保护数据资产。			
			
核心差异：默认管理员与预置模式			
• Oracle：默认的管理员账户是 SYS 和 SYSTEM。			
• KingbaseES：出于安全考虑，采用了“三权分立”的设计，初始化后默认创建三个管理员账户-			
• system：数据库管理员			
• sso：安全管理员			
• sao：审计管理员			
此外，KingbaseES在创建数据库时会默认生成 SYS_CATALOG（存放系统表）和 PUBLIC（通常作为默认模式）两个模式-			
			
权限与角色管理			
• 语法高度兼容：在用户和角色的创建、授权语法上，KingbaseES与Oracle高度兼容-			
• 创建用户：CREATE USER username IDENTIFIED BY password;			
• 授权：GRANT SELECT ON table TO user;			
• “用户”与“角色”：KingbaseES中，用户（USER）和角色（ROLE）本质上相同，核心区别在于用户拥有 LOGIN（登录）权限，而角色没有-			
• 权限模型：都采用“用户 → 角色 → 权限”的三层模型-			
• 系统权限：大部分Oracle的系统权限在KingbaseES中都有对应实现（如 CREATE SESSION 对应 LOGIN）-			
• 细粒度控制：KingbaseES支持更细粒度的权限控制，例如可以更灵活地控制 WITH GRANT OPTION 的传播-			
			
安全策略			
两者都提供强大的安全功能，但实现方式略有不同。			
安全功能		Oracle	
行级安全 (RLS)		通过 DBMS_RLS 包实现策略函数。	
密码策略		通过 PROFILE 配置文件管理。	
强制访问控制 (MAC)		需要额外购买 Label Security 选项。	
			
迁移时的核心注意事项			
理解上述差异后，在迁移时需要特别注意以下几点：			
1. 用户与模式的对应关系：Oracle迁移脚本中，用户和模式是等同的。在KingbaseES中，你需要显式地管理这种对应关系。例如，可以为每个迁移来的Oracle用户创建一个同名的模式，并将其设置为该用户的默认模式。			
2. 对象属主：在KingbaseES中，每个对象（如表、视图）都有一个“属主”（Owner），通常是指创建它的用户。规划迁移时，需要明确每个对象的属主是谁。			
3. 跨模式访问：由于用户和模式是分离的，用户要访问自己模式之外的对象，必须被显式地授予访问权限。迁移后，需要检查和重建这些跨模式的权限。			
4. 公共同义词（Public Synonym）：Oracle中常用的公共同义词在KingbaseES中可能不直接支持，可能需要通过创建视图或调整应用连接方式来替代。			
总而言之，虽然KingbaseES的Oracle兼容模式在语法层面非常接近，但其底层的用户和模式架构更为灵活。理解并利用好这种“分离”的特性，是成功从Oracle迁移并充分发挥KingbaseES优势的关键。
